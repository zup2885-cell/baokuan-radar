# 爆款雷达

电脑上的多平台选题和文案拆解工具。支持抖音、哔哩哔哩、YouTube 视频，以及 X 公开趋势。后台按平台节奏取榜、挑词、筛选和拆解，把文字与收藏留在本机。抖音仍需专用小号；其他平台不登录。

## 赛道设置（对标博主）

选题方向由「设置」里的四项决定：账号领域、中文固定词（抖音 / B站）、英文固定词（YouTube）和对标博主。提示词会读取保存的领域和对标列表，挑词与相关性判断按这个赛道进行；换赛道不需要改代码。

- 对标博主在设置页每行填 `名称｜平台`，平台填写「抖音」「B站」「YouTube」或「X」；最多 20 位、名称最多 60 字，同名同平台去重，清空即取消参考。对标只用于挑词提示，不会自动采集对标账号。
- 也可以把四项写成 JSON，通过本机接口局部更新（不触发搜索或模型调用，不直接改数据库）：

```sh
curl --fail-with-body -sS -X POST http://127.0.0.1:8777/api/settings \
  -H 'Content-Type: application/json' \
  --data-binary @docs-research/赛道设置.json
```

`docs-research/` 用来放某个具体博主的赛道研究和预设，只留在本机，已写进 `.gitignore`，不会提交到仓库。

每天关键词总数包含固定词：固定词占满名额时，热榜动态词就没有位置，需要调大每日总数。领域修改后，热榜下轮或点「补分类」重新判断，旧视频分析需自行「重新拆解」。

## 阿里云百炼与模型对比（2026-11-07）

### 配置与费用

双击桌面的「保存阿里云百炼密钥.command」保存密钥。本项目不创建或修改这个桌面脚本。也可在终端运行下面的命令，在 macOS 提示时输入密钥；不要把密钥直接写入命令、聊天、配置文件或日志：

```sh
security add-generic-password -U -s dashscope-api -a baokuan-radar -w
```

程序只通过 `security find-generic-password -s dashscope-api -a baokuan-radar -w` 在内存中读取。设置页仅显示状态，没有密钥输入框。密钥只通过 HTTPS Authorization 请求头发送，不写入日志、数据库、导出、错误信息或 Codex 提示词；HTTP 不跟随重定向，上游错误使用固定中文提示。请求使用北京地域的 `dashscope.aliyuncs.com`，真实验收须确认密钥地域、模型权限和余额。

无密钥时显示「未配置阿里云百炼」，继续使用本地 whisper + Codex。即使选择千问，也会回退 Codex，记录显示实际来源。已配置但千问调用失败时报告失败，保留旧分析，不额外调用 Codex。

百炼**按量计费，请查看控制台用量和账单**。语音识别按音频用量，筛选和分析按模型输入输出用量计费；分段产生多次请求，不合规重试也可能计费。本工具没有百炼硬性消费上限，YouTube API 日上限也不限制百炼费用。有密钥时，即使分析仍选 Codex，默认千问筛选和优先百炼转写也可能产生费用。

### 语音识别

选择 **`qwen3-asr-flash` 的 OpenAI 兼容文件识别**，因为它支持中文和英文，且无需新 SDK 或对象存储。接口为 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`。抖音、B站中文优先百炼；YouTube 仍优先人工或自动英文字幕，无字幕才用百炼英文识别或 whisper，英文保留原文供证据核对。

本地路径不能直接传给兼容 HTTP 接口。程序用已有 `~/.local/bin/ffmpeg` 转成 16 kHz、单声道 PCM WAV，每段 **180 秒**，通过 `input_audio.data` 的 Base64 Data URI 直接发送，无需 OSS 或临时公网 URL。官方单文件限制 **5 分钟、10 MB**，并要求 Base64 后也满足大小限制；本工具每段编码后约 7.7 MB，发送前再次检查时长和编码体积。设置 `asr_options.language=zh/en`、`enable_itn=true`，采用非流式结果，没有时间戳。

所有段成功后才按顺序拼接。任一段网络、额度、文件限制、转码或识别失败，都放弃部分结果，整条退回本地 whisper。中文用 macOS 自带 CoreFoundation/ICU 转简体；系统转换不可用时使用常见字表兜底（不覆盖所有生僻字）。`transcript_source` 记录实际来源 `aliyun-asr / whisper / subtitles / none`。临时媒体与分段结束后清理；已有逐字稿重新拆解时直接复用，不自动重新付费转写。

接口和限制依据 [Qwen-ASR API 官方文档](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)、[语音识别模型官方说明](https://help.aliyun.com/zh/model-studio/asr-model/)。本次只查文档与模拟测试，未发起真实百炼请求。

### 筛选、分析与历史对比

设置页分成两项，各自可选 Codex / 千问：

- **筛选模型（挑词、热榜分类、相关性）**：`screening_provider` 默认 `qwen`。用于各视频平台挑关键词，以及抖音、B站、YouTube 和 X 热榜的赛道分类与账号领域相关性判断。所有需要模型判断「要不要、选哪些」的步骤走筛选设置；不跟随分析设置。未配置百炼密钥时自动退回 Codex，不改已保存设置。每次挑词、分类都会先在运行记录中注明平台和实际模型，例如「YouTube挑词：千问（qwen-plus）」；无密钥回退也会注明，失败仍保留本次模型记录，不写密钥。
- **分析模型（爆款拆解）**：`analysis_provider` 默认 `codex`，只用于视频爆款拆解。保留用户已有设置。详情页仍可单次选择「用千问拆 / 用 Codex 拆」，不改变全局设置。

播放量、点赞、爆款倍数、发布时间、时长等数值门槛由本地规则计算，不调用模型；现有 YouTube 搜索结果的标题相关性排除也是本地规则。此次没有额外增加模型筛选请求。

Codex 沿用本机登录与现有额度；千问通过百炼兼容接口按量计费。筛选和分析选千问时共用 `qwen_model`，默认 **`qwen-plus`**。模型名可修改，但应选择支持非思考 JSON 输出的千问模型；不同模型的权限、费用和参数支持须在控制台确认，不保证任意模型名均可用。

千问请求包含现有 JSON Schema 和明确 JSON 指令，设置 `response_format={"type":"json_object"}`、`enable_thinking=false`。返回复用 `schemas/`、`validate_result`、账号领域及原文证据校验。JSON、结构或证据不合规时最多重试一次；两次失败显示中文错误。网络、鉴权和额度错误不自动重试。两种模型都可能判断错误，爆款原因仍是推测。参数依据 [百炼结构化输出官方文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

切换筛选模型不会重算已有有效分类或已生成的关键词；后续待分类词条和新关键词使用新设置。「查看分析」可切换保存的拆解结果。每个具体模型保留最近一次成功结果，修改千问模型名也保留原模型结果。失败不覆盖成功结果，收藏、标签、备注保留。旧数据标为 Codex。

筛选设置迁移在下次启动连接数据库时执行：仅当 `screening_provider` 这一行不存在时，写入 `"qwen"`；已有值、`analysis_provider` 及其他设置不因这项迁移改变，也不把缺失的分析设置写入数据库。本次只在临时数据库验证迁移和重复连接，**未连接或修改真实数据库**。

视频表新增 `analysis_provider`、`analysis_model`；`video_analyses` 保存每个模型的最近成功分析。导出仍只公开当前分析，新增模型来源，不导出其他历史版本或任何密钥。

连接数据库时会按主键列顺序核对分析历史表。旧版若仍使用 `(aweme_id,provider)` 两列主键，会在事务中重建为 `(aweme_id,provider,model)`，保留原分析和更新时间，再补入视频表中的当前分析。热榜和关键词表也会核对完整主键，避免仅包含平台列却缺少其他主键列。迁移失败会回滚；迁移成功后重复连接不再重建。离线回归见 `tests/test_migrations.py`，真实数据库留待另行验收。

### 门槛与升级

- B站、YouTube 默认最低播放 **50000**、最低爆款倍数 **2**，两个条件须同时满足；倍数为播放 ÷ 粉丝（YouTube 为订阅）。
- 抖音最低点赞沿用原值，最低倍数默认 **0（不限）**，倍数为点赞 ÷ 粉丝。
- 设置页可修改门槛，倍数支持小数。粉丝未知或为 0 时，倍数未知；最低倍数大于 0 时不选入，设 0 才放行倍数条件。既有发布时间条件继续生效。
- 下次连接数据库时事务迁移一次：B站/YouTube 缺省或仍等于旧默认 10000 的播放门槛更新为 50000，缺省最低倍数补为 2；其他已保存值保留。旧版没有逐项修改记录，无法区分「从未修改」与「主动改为旧默认 10000」，两者均迁为 50000。迁移后手动改回 10000 会保留。`auto`、平台开关、抖音最低点赞及其他设置不变。

本次未连接或修改真实数据库，默认值在工具下次运行时生效。新门槛用于后续搜索筛选，已完成分析及已有拆解队列保留。

离线验证：`python3 -m unittest discover -s tests`、`node tests/test_ui.js`。百炼测试全部模拟，不发真实请求。真实验收交接见 [tests/百炼验收说明.md](tests/百炼验收说明.md)。

## 多平台使用（2026-11-06）

在设置里分别开关抖音、B站、YouTube、X 趋势。**升级保留已有 `auto` 值，不会把用户关闭的自动运行打开；新增三个平台默认关闭。** `auto` 沿用原来的总调度开关，对所有启用的平台生效；手动「立即运行一次」可跳过自动开关和时段，仍遵守各平台间隔、日上限和暂停。只做电脑端开发与验收，没有新增移动端适配或动效。

| 平台 | 热榜/趋势 | 搜索与指标 | 文案来源 |
| --- | --- | --- | --- |
| 抖音 | 原公开热榜及赛道分类 | 原小号搜索，最低点赞独立设置；倍数 = 点赞 ÷ 粉丝 | 百炼中文识别优先，失败或无密钥用本地 whisper |
| B站 | 无登录公开热搜；复用赛道与领域相关性分类 | 既有 `bilibili-api-python`，按播放排序，SDK 日期范围加本地最近 N 天复核；读取播放、点赞、投币、收藏、分享、评论、UP 主粉丝 | yt-dlp 只下最佳音频，百炼中文识别优先，本地 faster-whisper 兜底，结束后删临时目录 |
| YouTube | 有钥匙串密钥时取美国 `mostPopular`，设置可选总榜或汽车（分类 2）；无密钥不显示此榜 | 有密钥：`search.list → videos.list → channels.list`；无密钥：`ytsearchN:`，不下载媒体，逐条读播放、点赞、订阅、上传日期 | 优先人工/自动英文字幕（只下字幕）；无字幕才下音频，用百炼英文识别或本地 whisper，结束后删字幕与音频 |
| X | 每天最多请求一次 trends24 美国页面，取最新一张时间榜 | 只做趋势，不搜推文、不登录、不做视频分析 | 无 |

X 搜索需要登录且反爬严格，官方 API 收费，因此这里只读取第三方公开趋势。trends24 不是 X 官方榜单，也不代表全平台热度；HTML 变化、验证码、拒绝或限流时显示暂不可用，不做浏览器伪装、挑战绕过或替换出口。X 当天请求失败也不再抓取，下一天才尝试。

B站和 YouTube 的**倍数 = 播放 ÷ 粉丝/订阅**，各自最低播放默认 5 万、最低倍数默认 2，须同时满足，可在设置修改；抖音最低点赞仍使用原值。未知或为零的粉丝/订阅显示倍数未知，真实 0 指标保留为 0。各平台倍数含义、热度值和数据口径不同，不能直接用来比较平台传播效果。YouTube 热榜展示的是公开视频播放计数，不是当天新增播放。

每轮每个启用的视频平台最多搜一个关键词，搜索间隔独立：抖音沿用原值，B站/YouTube 默认 30 分钟，范围 20–1440 分钟。后台实际仍每 30 分钟唤醒，不能保证精确到设置分钟；一轮合计最多拆 3 条，转写耗时会拉长后续处理。B站/YouTube 没有结果时将关键词记为已完成（`empty`，`found=0`），下一轮继续下一个词。同一个关键词连续失败达到 2 次（错误码可以不同），记为 `failed` 并跳过；成功后清零连续失败次数，计数按平台、日期、关键词分别保存。抖音以外的平台只有限流/风控（`RATE_LIMITED`、`PLATFORM_BLOCKED`）暂停 24 小时；普通热榜读取失败不会阻塞已有关键词，旧版普通错误留下的暂停也不再生效。不会切换通道继续尝试，也不影响其他平台。手动重新拆解同样不能跳过限流/风控暂停。已选视频保留到后续轮次，关闭平台后不自动处理其队列。

B站已确认一种有效空结果格式：SDK 返回 `numResults=0`、`numPages=0`，同时省略 `result`。适配器将其转换为 `{"ok": true, "items": []}`；缺少明确零计数的异常响应仍按读取失败处理。

每天关键词总数按**每个视频平台**分别计算。中文固定关键词用于抖音和 B站；YouTube 固定词单独设置，例如 `2026 SUV review, EV road test`，最多 10 个、每个 80 字。启用 YouTube 后，所选筛选模型会另做一次英文挑词，把账号领域翻成英文搜索词，理由仍用中文；生成的中文搜索词会被丢弃。固定词优先且计入每天数量，修改后从次日队列生效。每次挑词、分类或拆解都可能使用 Codex 额度或百炼按量计费。

YouTube 官方搜索指定美国、英文相关性、汽车分类（`videoCategoryId=2`）、播放量排序和时间范围；通过 `contentDetails.duration` 排除不足 60 秒、时长未知或标题含 `#shorts` 的结果。公开搜索也检查时长和 Shorts。排名前按汽车领域标题线索排除玩具、遥控模型、游戏等明显不相关内容，不增加 Codex 调用。挑词优先具体年份、车型或路测场景。已知非英文元数据会跳过，但语言元数据缺失时仍可能混入非英文内容；英文搜索词与区域参数无法保证所有结果都是英文。未知订阅数保留为空，隐藏订阅数不拿 0 代替。公开搜索不是完整全站排行榜。

YouTube 分析用中文，引用保留连续英文原句，并单独附中文意思。`analysis_youtube.json` 要求开头、原因、借鉴点的翻译字段；原句仍须通过输入文本校验。借鉴部分要求明确改成中文车评账号的口播场景和自有实拍素材。YouTube 逐字稿超过 7500 字时只发送开头 6000 字和结尾 1500 字，并在提示及 gaps 写明截断；证据只能出自实际发送的片段。有效文字不足 80 字时只据标题和描述分析，gaps 明确不能判断口播和实际开头。YouTube 单次分析超时上限为 480 秒。字幕接口单独返回 429 时改用音频转写，音频仍被拒绝时才暂停平台。旧中文分析继续兼容；翻译准确性和内容判断仍需人工核对。

### YouTube 密钥与配额

程序只用 `security find-generic-password -s youtube-api -w` 读取已有 macOS 钥匙串项；密钥只由 `platforms.youtube_key()` 在内存中取得，本次未配置或修改钥匙串。设置页只显示「YouTube 密钥：已配置 / 未配置」，没有密钥输入框。密钥只在内存中通过 HTTPS `X-Goog-Api-Key` 请求头发送给 Google，不放进 URL、命令行参数、日志、数据库、Codex 提示词或公开快照。

未配置时显示「未配置 YouTube 密钥」，只做公开关键词搜索；移除密钥后，本地界面也隐藏此前缓存的 YouTube 热榜。已配置但 API 失败时按上述规则重试、跳词或暂停，不自动切到公开搜索消耗另一条通道。每天官方搜索调用默认上限 10 次，可设 1–50 次；发请求前计次，失败也占次数。达到上限后返回 `DAILY_LIMIT`，北京时间下一天前不再发起官方搜索请求；关键词仍按连续失败 2 次的规则跳过，不新增平台暂停。此上限不是 Google 配额承诺，其他应用共用密钥、视频/频道查询、热榜和项目权限也会影响可用额度。

接口参数依据 [Google videos.list 官方文档](https://developers.google.com/youtube/data/reference/rest/v3/videos/list)、[search.list 官方文档](https://developers.google.com/youtube/data/reference/rest/v3/search/list)；字幕与下载参数依据 [yt-dlp 官方说明](https://github.com/yt-dlp/yt-dlp#usage-and-options)。本轮真实调用及限制见 [多平台验收说明](tests/多平台验收说明.md)。

### 数据兼容与公开演示

`videos`、`hot`、`keywords` 新增 `platform`（`douyin / bilibili / youtube / x`）；旧数据自动归为 `douyin`。视频旧 ID 原样保留，新增 B站/YouTube ID 为 `bilibili:BV…`、`youtube:…`；热榜主键为 `(platform,day,rank)`，关键词主键为 `(platform,day,word)`。首次连接在事务中迁移，重复连接不重建，原收藏、标签、备注、逐字稿和设置保留。迁移有临时旧库回归；本轮已通过工具流程连接正式库，保留用户原有设置。

今日爆款、收藏库有「全部 / 抖音 / B站 / YouTube」筛选，热榜另有「X」；列表和详情显示文字平台徽章及对应指标、倍数算法和原作品链接。赛道计数按当前平台计算，和相关性筛选取交集。`/api/videos`、`/api/hot`、`/api/tags` 支持 `platform=`；不传表示全部。

## 抖音原流程与通用操作

- 默认每天 **8:00–22:00（北京时间）**运行，后台每 30 分钟检查一次。电脑关机、休眠或退出当前 macOS 用户会影响运行，唤醒后才可能继续。
- 抖音每天取一次热榜，让所选筛选模型批量分类，再按账号领域生成关键词。热榜获取、分类和挑词分别记状态；分类失败不阻断挑词或热榜展示，后续轮次重试。
- 默认每天最多 6 个关键词，固定关键词计入总数且优先排列，重复词只算一次。每天的关键词选好后，当天不因修改领域或固定词重新生成，新的选题设置从下一天生效。
- 抖音默认每两次搜索至少间隔 60 分钟，一轮最多搜一个抖音词。「立即运行一次」可在自动运行关闭或运行时段之外手动处理一轮，仍遵守间隔和暂停规则。
- 每词最多读取 30 条搜索结果；默认挑点赞不少于 1 万、最近 7 天发布的前 3 条。一轮最多拆解 3 条，未拆完的已选视频留到后续轮次。当日没来得及搜索的词不会在第二天继续排队。
- 抖音爆款倍数 = 点赞数 ÷ 粉丝数。先按倍数、再按点赞数排序；粉丝未知或为 0 时显示「倍数未知」，排在已知倍数之后。发布时间缺失、无效或在未来的结果不会通过最近天数门槛。
- 同一视频只入库一份，已拆过的不会再次自动拆解，也不会覆盖收藏和备注。失败的视频可手动重试。
- 视频下载后优先用百炼转文字，无密钥或失败时用本地模型，正常结束或捕获到失败时删除视频，只留文字。下载或转写失败时，可基于标题进行拆解，并要求说明材料缺口；没有逐字稿的分析参考价值更低。进程被强制结束时，临时视频可能来不及删除。

「今日爆款」可切换历史日期；详情中能打开原视频、收藏、编辑标签和备注、复制模板。「收藏库」支持搜索标题、逐字稿、拆解、标签和备注，也可按标签筛选。修改标签或备注后记得点保存，自动刷新会保留正在编辑的内容。

## 热榜按赛道筛选

「热榜」顶部提供「全部」「和我相关」和各赛道按钮，当前按钮高亮，按钮后的数字是当天该类别的总条数，切换筛选不会改变这些总数。未分类也有独立按钮；未判断相关性不等于“不相关”，暂不计入「和我相关」。

赛道列表在 [`config/hot_tracks.json`](config/hot_tracks.json)，可以增删或调整顺序。每个热词只能归一个赛道，相关性另外判断；跨赛道但有自然结合点的话题，也可以与账号领域相关。配置必须是非空、不重复的文字列表，每项最多 20 字；「全部」「和我相关」「未分类」是保留名称。建议保留「其他」作为兜底类别。

分类通过所选筛选模型调用，把当天待分类词条一起发送，按 [`schemas/hot_classification.json`](schemas/hot_classification.json) 返回结果。程序检查原始排名、原词、数量、重复、赛道范围和布尔类型，全部合法后才一次入库。再次运行只处理未分类或已失效的词条，已有有效分类不会重复调用；挑词单独调用，便于分别重试。

旧数据库首次连接会自动为 `hot` 表补充 `track`、`related`、`classification_key`，并按上文增加多平台列与主键，保留热词和其他数据。今天已抓过的热榜也会在下一次有效 tick（自动时须在运行时段内）补分类。也可在热榜页点「补分类」：按平台分别分类已存在的今日热词，不抓榜、不搜索，也不打开登录或验证窗口；任务仍使用原来的共用锁。

分类失败时热词保留，显示「未分类」，运行记录说明失败，下一轮自动重试。修改「账号领域」或赛道配置后，旧分类立即按未分类显示，下一轮或点「补分类」重新判断；已经选好的当天关键词继续沿用，下一天才重新选词。

接口：`GET /api/hot?day=YYYY-MM-DD` 返回 `items`、`tracks`、`counts`、`field`、`day`；可加 `track=汽车`（中文需 URL 编码）或 `related=1`，两者并用时取交集。`related=0` 关闭相关筛选。`counts.all`、`counts.related`、`counts.tracks` 始终按整天计算，缺失热度保留为空、真实的 0 保留为 0。`POST /api/classify-hot` 使用任务队列补分类。

## AI 爆款分析

视频详情的「AI 爆款分析」保留总结、开头钩子、结构、模板、角度、受众、原因、标签和材料缺口，并增加：

- **开头前 3 秒分析**：引用开头文字，说明具体手法和可能留人的理由。现有转写没有逐句时间戳，只能按开头文字推测，无法确认真实前 3 秒；只有标题时不能判断实际开头。
- **爆款原因**：2–4 条，每条带连续原文证据并标为「推测」。用反事实问题寻找主要机制，考虑情绪、分享动机、留人和内容兑现，也考虑粉丝基础、时机、投流未知、随机性和单样本偏差。
- **值得借鉴**：逐条给原文证据，以及如何用到当前账号领域的具体场景和改法。
- **不建议照搬**：说明不能直接复用的内容、原因及替代做法。
- **可以直接改的选题**：2–3 个，包含原创开场、内容提纲和借鉴的机制，缺少个人实证时应补自己的素材。

新版结果使用 `analysis_version: 2`，记录分析时的 `account_field`。程序校验结构、必填字段、条数和推测标记；钩子、开头证据、原因和借鉴点的引用还须出现在实际输入的逐字稿或标题中。校验不能保证解释正确，仍需要人工判断。

旧结果直接读取，无需补字段或批量重算；界面提示「旧版分析」。点「重新拆解」使用当前领域生成新版，优先复用逐字稿，保留收藏、标签和备注。重新拆解失败时，界面保留上次结果并显示失败提示。修改领域不会自动重算旧分析，详情会提醒重新拆解。

目前没有把视频画面、音频、完播率、留存曲线或评论正文送入分析，不能据此声称看到了镜头、听到了语气，或证实了推荐原因。

## 数据存在哪

默认数据目录：`~/Library/Application Support/BaokuanRadar`。

在访达选择「前往」→「前往文件夹」，粘贴这个路径即可打开。

| 文件或文件夹 | 内容 |
| --- | --- |
| `radar.sqlite3` | 设置、热榜、关键词、视频信息、逐字稿、拆解、收藏、标签、备注和运行记录 |
| `dy-account/cookies/default.json` | 专用小号的登录资料，请勿分享 |
| `dy-account/browser-profile` | 小号独立浏览器资料，请勿分享 |
| `media` | 临时视频，转写后删除；强制终止产生的残留可在确认任务未运行时清理 |
| `logs/server.log`、`logs/tick.log` | 安装后台任务后产生的服务和定时任务日志 |
| `codex-out`、`*.lock` | 临时结构化输出和任务锁文件，锁文件存在不代表任务还在运行 |

备份前先停止后台任务，再复制整个数据目录。不要把账号资料、逐字稿或日志放进公开仓库。开发和测试可在启动进程前设置 `BAOKUAN_DATA` 来换数据目录，界面服务与定时进程必须使用相同目录；默认安装脚本仍使用上述正式目录。

## 怎么卸载后台任务

在「爆款雷达」目录打开终端，执行：

```sh
./install.sh remove
```

这会停止并移除界面服务和每 30 分钟的任务，不删除收藏、账号资料和工具代码。需要恢复时重新执行 `./install.sh`。关闭网页只会关闭界面，不会停止后台搜索；临时停用可在「设置」关闭「每天自动运行」并保存。

## 风险和判断边界

**这是非官方读取方式，违反抖音用户协议，小号可能被限制或封禁，务必用专用小号。** 放慢频率也不能保证账号安全。遇到验证码和风控就停下来，由本人处理；工具不破解验证码，也不绕过验证。

公开热榜、网页结构和视频下载地址可能变化或失效，粉丝、点赞等数据可能缺失；筛选只代表页面返回的有限样本，不能保证找到全平台爆款。倍数高不等于内容一定好，也不能排除投流等因素。语音识别可能有错字，Codex 对爆款原因的解释是推测，需要自己复核。

有百炼密钥时，语音片段发送给百炼识别；无密钥或识别失败才在本机转写。热榜分类、挑词和文案拆解会把热榜、账号领域、视频描述、指标和逐字稿发送给所选的 Codex 或千问服务。分类与挑词是独立调用，失败重试及修改领域后的重分类也可能使用 Codex 额度或百炼费用，不能理解为全程离线。

## 给维护和验收人员

无需安装测试依赖。在当前目录执行：

```sh
python3 -m unittest discover -s tests -v
node tests/test_ui.js
python3 -m py_compile radar.py server.py dy_worker.py transcribe.py tests/test_radar.py
```

多平台测试也包含模拟密钥、官方 API、公开搜索、字幕优先、音频清理与逐平台暂停；无真实密钥读取。单元测试使用标准库和临时 `BAOKUAN_DATA`，模拟搜索、Codex、下载、转写与 HTTP 请求处理；真实网络、外部进程和通知都被拦截，不会打开浏览器、操作抖音或改动正式数据库。新增覆盖旧库迁移与重复连接、分类入库与重试、完整性校验、赛道/相关筛选及计数、设置变化时分类失效、新分析校验、原文证据、旧分析读取与重新拆解。

`tests/test_model_routing.py` 另覆盖筛选和分析设置的全部组合、各平台挑词和分类、单次拆解覆盖、无密钥回退、成功或失败时的模型日志、设置 API 独立保存与非法值拒绝，以及迁移只补缺失值且不覆盖已有设置。界面离线测试检查两个下拉框的默认值、读取、保存和刷新时保留未保存的选择。

`node tests/test_ui.js` 离线检查界面断线恢复、请求返回顺序、编辑内容保留、设置刷新、赛道按钮和计数、空状态、新旧分析排版结构、证据转义与重新拆解请求。另检查生成页的静态模式：仅一次相对 JSON 请求、无 `/api` 或外部脚本请求、无轮询，并检查封面来源白名单和未拆解收藏状态，五页签、摘录复制、收藏搜索和标签筛选、热榜筛选、写入操作拒绝及失败/空状态。Python 的 `tests/test_export_demo.py` 使用临时数据库验证字段白名单、敏感内容与路径脱敏、摘录长度、日期范围、只读 URI、数据库字节未变、旧库无迁移及生成页同步。它们使用模拟页面元素，不属于真实浏览器的视觉验收。
